# v1.0.0 · g2rain-main-shell 首个稳定版

G2rain（谷雨）是面向企业的开源智能体平台，连接模型、知识与业务工具，并提供 SaaS 基座、应用开发和部署能力。`g2rain-main-shell` 是平台前端应用层的微前端主应用：它只负责统一布局、导航、路由、Tab、子应用生命周期以及浏览器侧 SSO/Token 协调；它不提供子应用业务规则、IAM 的 Token 签发、Gateway 最终鉴权或整个平台能力。

## 交付、构建与镜像

- 项目版本事实源为根 `package.json` 与 `package-lock.json`，均为 `1.0.0`；许可证为根目录标准 Apache License 2.0（`Copyright © 2025 g2rain.com`）。
- 构建要求为 Node.js 22+ 与 npm；`npm ci` 使用锁文件安装依赖，`npm run build` 执行 `vue-tsc` 与 Vite 生产构建。本仓没有 `npm test` 脚本。
- 镜像为 `ghcr.io/g2rain/g2rain-main-shell:1.0.0` 及 `ghcr.io/g2rain/g2rain-main-shell:sha-<完整提交 SHA>`；稳定版不推送或更新 `latest`。
- 本地和 CI 都复用根目录 `Dockerfile`：Node 22 Alpine 构建静态资源，OpenResty Alpine 运行，入口为 `/docker-entrypoint.sh`，镜像声明端口 `8080`，而 `SERVER_PORT` 默认监听 `80`，部署必须显式映射并设置实际端口。
- OCI 标签包括源码与 URL、`g2rain-main-shell` title、版本、提交 revision 和 `Apache-2.0` 许可证。

## 发布顺序与权限

按 `feature/* → develop → main` 流程，先将版本、工作流和本说明合入 `main`，完成验证后在该 `main` 提交创建并推送 `v1.0.0`。工作流只响应推送的严格稳定版 tag，验证 tag 格式、提交位于 `origin/main` 历史、该提交内同名非空发布说明和 `package.json` 版本；随后运行 `npm ci` 与 `npm run build`，再构建并推送两个镜像标签。它只使用 `GITHUB_TOKEN`、`contents: read` 和 `packages: write`，不创建 GitHub Release、不部署服务也不更新 `latest`。只有两个标签均推送成功才写入 Actions Summary。

首次推送成功后，如需匿名拉取，在 GitHub Packages 的 **Package settings → Change visibility → Public** 将包公开；若组织管理员禁止修改，请联系管理员。已有包即使已声明 `packages: write`，也可能需要在 **Package settings → Actions access** 授予 `g2rain/g2rain-main-shell` 写权限；遇到 `denied` 时先检查该设置和组织 Packages 策略。公开后可拉取：

```bash
docker pull ghcr.io/g2rain/g2rain-main-shell:1.0.0
```

## 镜像内容、配置与安全

最终镜像包含 Vite `dist/`、`lua/sign.lua`、`lua/sign_api.lua`、`lua/config.lua`、Nginx 模板和入口脚本；它不复制 `lua/keys/`。生产环境必须通过只读 volume、Docker/Kubernetes Secret 或等效密钥管理服务向 `/usr/local/openresty/nginx/lua/keys/` 注入 `private-key.pem`、`public-key.pem`、`iam-public-key.pem` 和 `iam-key-id.txt`，并按密钥轮换流程更新。`VITE_*` 和运行时 `SSO_BASE_URL` 面向浏览器，不能包含 Secret。

仓库仍跟踪 `lua/keys/private-key.pem`、`public-key.pem`、`iam-public-key.pem` 和 `iam-key-id.txt`。虽然这些文件已由 Docker 构建上下文排除且不进入发布镜像，维护者仍须在公开源码前确认它们仅为可公开样例；如含真实或曾复用的凭据，必须先替换、迁移并轮换。`.dockerignore` 不解决 Git 历史或仓库可见性风险。

本次发布准备需分别记录：本地构建、CI 构建和测试、容器构建、GHCR 推送、匿名拉取、在线演示与实际部署验证；任何一项成功均不代表其他项已经完成。自动验证范围是依赖安装、类型检查和 Vite 构建，没有独立测试脚本；它不证明 IAM/Gateway/Lua 签名联调、真实子应用挂载、深链刷新、容器启动、GHCR 推送、匿名拉取或目标环境部署。发布前仍应验证 `/main`、静态资源、深链刷新、SSO 回调、API/Auth 代理和至少一个真实子应用。
